**P02-T04 candidate policy:** ZIP crate không thay thế giới hạn Q36 hoặc path safety. Vì reader dựng index central-directory trước khi đọc payload, candidate thêm `max_central_directory_bytes = 64 MiB` làm cap metadata riêng, không thay ba giới hạn payload Q36. Trước khi indexing, implementation chọn duy nhất EOCD kết thúc đúng tại EOF, từ chối EOCD signature trong comment, đọc đúng `entry_count` central records bằng buffer cố định, kiểm độ dài từng record bằng checked arithmetic và bắt directory kết thúc đúng tại ZIP64 EOCD/EOCD; không tin riêng size khai trong end record. Preflight trả cả số entry lẫn `archive_offset` đã suy ra từ physical central-directory start và offset logic khai báo. Candidate phải dựng `ZipArchive` bằng `with_config` và `ArchiveOffset::Known(archive_offset)` để thư viện đọc đúng view mà preflight đã giới hạn; không để `Detect` quét và chọn một ZIP64 EOCD hoặc central directory khác. Archive có prefix vẫn được hỗ trợ khi offset được kiểm nhất quán với ZIP64 locator. Ca hồi quy đặt một ZIP64 EOCD giả hợp lệ trong vùng prefix và xác nhận chỉ entry của view thật được đọc.

ZIP64 extensible data sector ngoài payload cố định 44 byte bị từ chối vì thư viện cấp phát buffer theo chiều dài sector. Hỗ trợ central-directory digital signature chỉ khi record tiêu thụ chính xác phần còn lại đã nằm trong cap. Reader đếm bytes do wrapper quan sát; sau bất kỳ lỗi tạo reader/đọc/kiểm tra payload, session đóng vĩnh viễn để không thể retry hoặc chuyển entry nhằm né giới hạn. Tên đích Windows phải kiểm cả ancestor file/directory, không chỉ tên đầy đủ. Kiểm tra dưới/bằng/+1 dùng caps test nhỏ; default Q36 vẫn 10,000 entries, 128 MiB actual bytes mỗi entry và 1 GiB actual bytes mỗi phiên. Xem [P02-T04 assignment r03](../roadmap/evidence/phase-02/P02-T04.assignment-r03.md), amendment r04 và review r01/r02 tương ứng.

**P02-T05 XML candidate policy (v0.25):** Pin `roxmltree` 0.21.2 exactly, defaults off, only `std` + `positions`. Decode bounded entries as UTF-8/UTF-16, cap raw and decoded documents at 16 MiB and parsed nodes at 1,000,000. Before invoking the parser, run a bounded lexical entity-expansion preflight that conservatively calculates the projected expanded UTF-8 document/work size for internal general-entity references in text and attributes; reject over-budget input before `roxmltree` allocates expanded text. Preflight work must be linear in decoded document and entity-definition bytes, or stop at a dedicated work cap with a located incomplete diagnostic; malformed references must never trigger repeated suffix scans. Projected expanded document size may not exceed 16 MiB. The parser’s 10-level and 255-reference limits remain secondary safeguards, not the aggregate budget. Enable only required DTD syntax; the external-entity callback always rejects and performs no file/network I/O. Unknown, blocked, unsupported or over-limit input becomes a located incomplete diagnostic. No href/XInclude/CSS/script/media dereference occurs in the parser; resources are read only through T04 validated entries. Keep XML limits separate from Q36 ZIP payload caps. Tests inject small limits for below/equal/above cases, including root-repeat and nested expansion.

This is an A decision candidate to make T05 implementation concrete, not a prior approved requirement. B must inspect the pinned crate source, namespace and encoding behavior, entity callback, and limit tests before approving D03. Source basis: [roxmltree 0.21.2 Cargo features/MSRV](https://github.com/RazrFalcon/roxmltree/blob/v0.21.2/Cargo.toml), [ParsingOptions and limits](https://docs.rs/roxmltree/0.21.2/roxmltree/struct.ParsingOptions.html), [parser behavior](https://github.com/RazrFalcon/roxmltree/blob/v0.21.2/docs/parsing.md), and [EPUB 3.3 XML constraints](https://www.w3.org/TR/epub-33/#sec-xml-conformance).

Nguồn chính thức: [zip-rs changelog](https://github.com/zip-rs/zip2/blob/master/CHANGELOG.md), [Cargo features and rust-version](https://github.com/zip-rs/zip2/blob/master/Cargo.toml), [ZipArchive API](https://docs.rs/zip/latest/zip/read/struct.ZipArchive.html), [ZipFile API](https://docs.rs/zip/latest/zip/read/struct.ZipFile.html).

Manifest thử nghiệm cụ thể và lockfile: [`P00-T02-compat/Cargo.toml`](../roadmap/evidence/phase-00/P00-T02-compat/Cargo.toml), [`Cargo.lock`](../roadmap/evidence/phase-00/P00-T02-compat/Cargo.lock). Các dependency trong spike dùng version exact để kết quả tái lập. Feature list và consumer trong bảng là quyết định của task; chưa phải yêu cầu thêm dependency vào mọi crate.

`cargo tree --manifest-path docs/roadmap/evidence/phase-00/P00-T02-compat/Cargo.toml --locked --offline -e features -i crossterm` xác nhận chỉ một `crossterm 0.29.0` được hợp nhất cho direct dependency và backend Ratatui. `ratatui-crossterm` bật `crossterm_0_29` cùng `underline-color`; đường backend cũng bật default `derive-more` của Crossterm dù direct dependency khai báo `default-features = false`. Vì vậy không tuyên bố toàn bộ graph đã tắt default; các feature IO này thuộc TUI. Spike không có package Domain nên chưa phải kiểm tra graph giữa các crate; P00-T03/P01-T03 xác minh boundary thật.

**Theo consumer:** T02-r02 đã hoãn runtime/async trait khi chưa có consumer. Lựa chọn event loop cho shell Phase 01 được chốt bổ sung tại §8 theo P00-T04; không thêm Tokio cho shell đồng bộ. SQLite/rusqlite (P00-T06); HTTP/reqwest/provider (phase sử dụng); IPC, credential store và export (phase sử dụng) vẫn hoãn đến consumer. Không thêm các dependency này vào Domain hoặc workspace nền tảng khi chưa có consumer được giao.

## 3. MSRV, edition và resolver

Rust 2024 được hỗ trợ từ Rust 1.85 và mặc định resolver 3; Rust 1.88 được chọn để đáp ứng Ratatui 0.30.2. Manifest spike khai báo `edition = "2024"`, `rust-version = "1.88"`, `[workspace] resolver = "3"`. Lockfile được sinh bằng Cargo 1.97.1 trước khi pin toolchain; Cargo báo chọn 118 package tương thích Rust 1.88. Việc này là bằng chứng resolve, không thay cho test bằng compiler 1.88.0.

## 4. Ranh giới phụ thuộc

- `ratatui`, `crossterm` và `unicode-segmentation` thuộc TUI; `crossterm_winapi` chỉ thuộc adapter đọc record phím native của `nt-tui` trên Windows; `clap` và `tracing-subscriber` thuộc app composition boundary.
- `tracing` chỉ dùng ở crate có consumer logging. `serde`/`serde_json` chỉ dùng cho DTO ở boundary có schema; không biến entity Domain thành wire format mặc định.
- `thiserror` phục vụ kiểu lỗi tường minh; `anyhow` chỉ thêm ngữ cảnh tại binary. Mọi lỗi vẫn phải giữ nguyên nhân và quy tắc redaction của spec.
- Không có Tokio, IO, DB, HTTP hay adapter dependency trong Domain. Việc thử compile một API không cấp quyền đưa thư viện đó vào crate không có consumer.

## 8. P01-D05 — Event loop cho shell Phase 01

P00-T04 chọn event loop đồng bộ cho shell Phase 01; P01-T12 điều chỉnh cách chờ sau khi probe native tái hiện viewport đổi mà không có input record. Loop chờ event tối đa 100 ms, đọc event nếu có, rồi kiểm tra lại kích thước terminal sau event hoặc timeout. Trên Unix dùng `event::poll()` rồi `event::read()`; trên Windows chờ console input handle với `WaitForSingleObject` trước khi giữ nguyên adapter đọc `KEY_EVENT_RECORD`. Nếu timeout không có thay đổi kích thước, không render lại frame. Đây là lần chờ hữu hạn trong cùng vòng lặp, không thêm async runtime, timer nền, thread hoặc async trait. Crossterm `event::poll`/`read` dùng event source đồng bộ; raw mode để input có thể đi qua event source; Ctrl+C chỉ là shutdown request nếu event source thực sự nhận được event đó. [Crossterm event module 0.29](https://docs.rs/crossterm/0.29.0/crossterm/event/index.html), [Crossterm terminal raw mode 0.29](https://docs.rs/crossterm/0.29.0/crossterm/terminal/index.html), [WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject).

Source event được bọc sau seam private để unit/contract test đẩy event xác định, không sleep để chờ timer. P01 render không ghi dữ liệu nghiệp vụ và không gọi model. Nếu phase sau thêm I/O async, retry/timer hoặc IPC, đánh giá runtime ở task consumer trước khi thêm dependency; không đưa runtime vào Domain.

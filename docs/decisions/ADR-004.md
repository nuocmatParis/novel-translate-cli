# ADR-004 — Generation CAS, file reference và migration cơ bản

**Ngày:** 08/11/2026 · **Phiên bản:** 0.5  
**Trạng thái:** Contract kỹ thuật T08 tại v0.4 được B review độc lập **Đạt** trong candidate P00-T06–T08-r04 cho AC08, phạm vi Windows spike; F03–F05 đóng. v0.5 chỉ ghi owner/hạn cho garbage collection theo T09, không đổi contract T08. Production schema/write path Phase 02 chưa triển khai; các giới hạn durability ghi ở §5 vẫn cần nghiệm thu trước release.  
**Phạm vi:** Series DB schema bootstrap và generation/file write path ban đầu; chưa chốt Coordinator, Markdown projection hoặc updater release.

## 1. Căn cứ

`P00-AC08`/`P00-TC08` yêu cầu trạng thái mỗi điểm ngắt, reopen thấy generation cũ hoặc mới trọn vẹn và DB không tham chiếu file chưa hoàn tất. Căn cứ đã chốt là [Q06](../spec/DESIGN_DECISIONS_36.md#decision-06), [Q07](../spec/DESIGN_DECISIONS_36.md#decision-07), [DB-07/08/12/18](../desgin/DATA_ARCHITECTURE_STEP6.md) và [P00-T08](../roadmap/phases/PHASE-00.md#p00-t08). DDL tên mẫu không bị coi là yêu cầu schema.

## 2. Contract generation

- Khi tạo Series DB, một `BEGIN IMMEDIATE` transaction tạo DDL, bootstrap generation, file reference, current pointer và `PRAGMA user_version = 1` cùng nhau; không dùng ID rỗng để biểu diễn “chưa có current”.
- Nếu process dừng trước commit transaction bootstrap, SQLite rollback cả DDL và dữ liệu. Object đã hard-link hoàn chỉnh có thể còn không được tham chiếu; lần tạo lại xác minh và tái sử dụng đúng object, sau đó tạo g0/schema version trong transaction mới. Nếu kết quả commit chưa rõ, mở DB và xác minh schema version, current generation cùng hash trước; không chạy lại `CREATE TABLE` trên DB đã commit.
- Mỗi operation có operation ID ổn định, expected parent generation, immutable object hashes và candidate generation. Generation, refs, history/change records và CAS current pointer được ghi trong cùng `BEGIN IMMEDIATE` transaction.
- Đọc current trong transaction; chỉ tiếp tục nếu current bằng expected parent. `UPDATE ... WHERE generation_id = expected` phải tác động đúng một row; nếu không rollback và trả `StaleGeneration`.
- Replay cùng operation ID, parent và hashes đã commit trả lại generation cũ mà không chuyển current lùi. Dùng lại ID với payload/parent khác bị từ chối. Operation ID mới trên parent cũ trả stale.
- Lịch sử generation cũ và file bất biến không bị sửa/xóa trong publish. Orphan object sau stale/crash là trạng thái hợp lệ; garbage collection là bước riêng sau khi rà references. [P02-T02](../roadmap/phases/PHASE-02.md#p02-t02) nhận chính sách/orphan inventory trước khi thêm GC; việc GC chưa có không chặn file store ban đầu. Lịch tương ứng nằm ở [ROADMAP §4.1](../roadmap/ROADMAP.md#decision-schedule).

## 3. Trình tự file rồi DB

1. Tạo temp file unique bằng `create_new` trong cùng object-store directory/volume; ghi đủ byte, `sync_all`, đóng file.
2. Tạo hard link từ temp đã flush sang tên bất biến `<lowercase-hash>.blob` trong cùng thư mục/filesystem. Thao tác này không thay thế target đã có. Nếu target đã xuất hiện đồng thời, đọc và xác minh toàn bộ byte/hash; chỉ dùng lại khi khớp, còn sai thì trả lỗi và giữ target ban đầu nguyên trạng.
3. Đọc lại object sau publish và xác minh hash trước khi mở transaction DB.
4. Mở `BEGIN IMMEDIATE`, CAS expected generation, thêm generation + file refs, cập nhật current, commit.
5. ACK thành công chỉ sau DB commit. Nếu ACK mất, caller reconcile operation ID; không tự đoán đã/ chưa commit.

DB không thể rollback file ở filesystem. Tính đầy đủ được xác minh bằng hash trước khi tạo reference; không gắn đường dẫn temp vào DB. Nếu hard link không được filesystem hỗ trợ hoặc tạo link lỗi, publish dừng trước DB reference; object store cần nằm trên filesystem hỗ trợ hard link và cùng volume với temp. Process-crash probe xác nhận không ghi đè trên NTFS cục bộ; độ bền của directory entry khi mất điện hoặc lỗi kernel chưa được đo.

## 4. Điểm ngắt và khôi phục

| Điểm ngắt | Trạng thái sau process exit/reopen trong spike | Hành vi |
|---|---|---|
| Trong lúc ghi temp | DB/current vẫn generation cũ; có thể còn temp dở dang chưa được reference. | Không đọc temp như object; dọn sau khi xác nhận không có writer khác dùng nó. |
| Sau hard-link publish object, trước transaction generation | Current generation cũ; object hoàn chỉnh chưa được reference (orphan). | Giữ nguyên current; GC riêng xử lý sau. |
| Sau mọi DDL, insert g0/ref/current và schema version trong transaction bootstrap, trước commit | Sau process exit, DB không có bảng ứng dụng, `user_version` vẫn 0; object bootstrap hoàn chỉnh còn không được tham chiếu. | Thử lại bootstrap an toàn: tái xác minh object hash, rồi tạo schema, g0, reference, current và version 1 trong transaction mới. |
| Sau insert/update trong transaction, trước commit | SQLite rollback toàn transaction khi process chết; current/history cũ. File mới vẫn orphan. | Reopen kiểm current cũ và refs cũ. |
| Sau commit, trước ACK/caller exit | Current mới cùng mọi refs; file đã được hash-check trước transaction. | Reopen trả new generation; operation ID cho phép caller biết commit đã xong. |
| Object referenced bị thiếu/corrupt khi kiểm integrity | DB row vẫn ghi lịch sử, nhưng storage không dùng object sai. | Fail closed, chặn ghi và báo repair/reconcile; không âm thầm chọn ancestor hay xóa lịch sử. |

P00 spike đã `abort` tiến trình con tại bốn điểm của generation (`during-file`, `after-file`, `before-commit`, `after-commit`) và một điểm bootstrap (`bootstrap-before-commit`). Mỗi child ghi marker tên điểm ngay trước khi abort; parent từ chối exit 90 của nhánh trả về bất ngờ và xác nhận marker khớp. Bốn điểm generation được mở lại và kiểm trạng thái current, số generation, file temp hoặc object hoàn chỉnh tương ứng. Điểm bootstrap được mở lại để xác nhận không còn bảng ứng dụng hay schema version, sau đó retry và kiểm schema 1, g0, reference cùng hash. Hai regression interleave xác nhận target object sai byte được giữ và không được tham chiếu; target có cùng payload được dùng lại mà timestamp/file không bị thay. Đối chứng đổi hard link về `rename` làm cả hai regression thất bại. Current là g0/g1 hợp lệ, đúng hash; một object lỗi/thiếu bị integrity check từ chối. Đây là **process crash trên Windows**, không phải mô phỏng mất điện/kernel crash.

## 5. Durability boundary

Series DB dùng WAL local và `synchronous=FULL`; mọi connection bật foreign keys. SQLite mô tả FULL trong WAL là atomic/consistent/isolated/durable và WAL yêu cầu process trên cùng host, không phù hợp network filesystem. File object được ghi bằng `File::sync_all`, rồi hard-link trong cùng directory/filesystem và verify lại trước DB transaction. Test Windows này không cắt điện, không ép filesystem/device cache và không xác minh độ bền directory entry của hard link trên mọi filesystem Windows. Vì SQLite transaction và file object là hai hệ thống lưu trữ, không tuyên bố atomicity phân tán hoặc power-loss guarantee cho cả hai.

Khi mở DB, storage phải xác minh hash các file của current generation trước khi dùng. Nếu OS/power failure làm file tham chiếu thiếu hoặc sai hash, giữ history, dừng ghi và yêu cầu recovery; không tự rollback pointer khi chưa có chính sách dữ liệu chấp nhận được. Độ bền của object name khi mất điện trên filesystem đích cùng cơ chế durable publish/recovery phải được kiểm trước release/updater.

## 6. Migration và backup

- Lưu schema version bằng `PRAGMA user_version`; migration DDL và đổi version chạy cùng transaction. Migration không mutate object store.
- Trước thay đổi schema, dừng writer/GC và tạo SQLite online backup; tạo restore set gồm mọi object hash đang được DB tham chiếu, manifest/version, current generation và hash verification.
- Thử migration/`integrity_check`/foreign-key check trên bản staging. Lỗi giữa DDL phải rollback toàn bộ migration; source DB và objects giữ nguyên. Chỉ đưa staged set vào dùng sau khi verify DB + file refs. Giữ bản backup tới lần mở thành công.
- Cách thay thế hai kho lưu trữ cùng lúc trên Windows, cleanup backup và tiến trình updater chưa được thử ở P00; không dùng một `rename` của DB để tuyên bố DB + files đã atomic.

Spike kiểm backup DB bằng rusqlite backup API, copy/hash toàn bộ object được reference, migration fixture v1→v2 và lỗi sau DDL. Nó không migrate dữ liệu người dùng, không sửa file EPUB/Markdown, không thay đổi format Go cũ.
